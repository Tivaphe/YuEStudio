## 1 bis. README affiché par défaut

GitHub affiche toujours `README.md`. Deux options :

- **Garder `README.md` en français** (choix actuel) : le public visé est francophone, et
  `README.en.md` est lié dès la première ligne.
- **Inverser** si vous visez l'international : renommez `README.en.md` → `README.md` et
  `README.md` → `README.fr.md`, puis corrigez les deux liens croisés en tête de chaque fichier.

Les deux fichiers sont à jour et se renvoient l'un vers l'autre.

```

```

**Pourquoi ces choix :** `yue2` / `yue2-3b` / `audio-cpp` / `gguf` captent les recherches par nom de
modèle et de moteur (les plus intentionnelles). `music-generation` / `text-to-music` /
`lyrics-to-song` / `ai-singing` sont les termes génériques les plus recherchés du domaine.
`local-ai` / `offline-ai` / `on-device-ai` ciblent la vraie différenciation du projet : rien ne part
dans le cloud. `windows-app` / `python` / `no-dependencies` / `french` qualifient la nature du livrable.

## 5. Première release

- **Tag** : `v1.0.0`
- **Titre** : `YueStudio 1.0.0 — première version`
- **Fichier joint** : `dist/YueStudio.zip` (70 Ko). Renommez-le en `YueStudio-1.0.0.zip` pour que le
  numéro de version apparaisse dans le nom du fichier téléchargé.
- **Note importante à écrire dans la release** : l'archive ne contient **que le code**. Le moteur
  audio.cpp (~1 Go) et les poids YuE2 (~4 à 13 Go) sont téléchargés par `1-INSTALLER.bat` depuis
  leurs dépôts officiels, car les poids sont sous licence **CC BY-NC 4.0** et ne peuvent pas être
  redistribués ici.

## 6. Avant de publier : la vérification en 30 secondes

```
git status                     # rien de généré ne doit apparaître
git ls-files | wc -l           # 21 fichiers attendus
git ls-files | grep -Ei "engine/|models/|historique.json|\.wav$|\.gguf$|\.pid$"   # doit être vide
```

Le `.gitignore` couvre déjà `engine/`, `models/`, `Mes chansons/`, `historique.json`,
`yuestudio.pid` et `*.log` — cette commande sert juste à s'en assurer avant le premier push.
