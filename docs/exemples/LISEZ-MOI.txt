Exemples audio référencés par les README :

    2026-09-19_135052_cyber.mp3   écoute directe dans le navigateur (3 Mo, 192 kbps, 2 min 06)
    2026-09-19_135052_cyber.wav   version sans perte (24 Mo, 48 kHz / 16 bits stéréo)

(morceau « cyber », instrumental synthwave généré en local par YueStudio — YuE2-3B)

Pourquoi deux fichiers ? Le MP3 est celui à utiliser pour l'écoute en ligne : GitHub sert ses
fichiers bruts avec l'en-tête « Content-Disposition: attachment », donc un lien
« raw.githubusercontent.com » force le téléchargement au lieu de la lecture. Le bouton
« Écouter » des README passe donc par jsDelivr, qui sert le même fichier du dépôt avec le bon
type MIME (audio/mpeg) et sans cet en-tête :

    https://cdn.jsdelivr.net/gh/Tivaphe/YuEStudio@main/docs/exemples/2026-09-19_135052_cyber.mp3

Pour régénérer le MP3 depuis le WAV :

    ffmpeg -i 2026-09-19_135052_cyber.wav -c:a libmp3lame -b:a 192k 2026-09-19_135052_cyber.mp3

Audio samples referenced by the readmes:

    2026-09-19_135052_cyber.mp3   streams in the browser (3 MB, 192 kbps, 2 min 06)
    2026-09-19_135052_cyber.wav   lossless original (24 MB, 48 kHz / 16-bit stereo)

("cyber", a synthwave instrumental generated locally by YueStudio — YuE2-3B)

Why two files? Use the MP3 for online listening: GitHub serves its raw files with a
"Content-Disposition: attachment" header, so a "raw.githubusercontent.com" link forces a
download instead of playback. The readmes' "Listen" button therefore goes through jsDelivr,
which serves the same in-repo file with the proper MIME type (audio/mpeg) and without that
header.

To rebuild the MP3 from the WAV:

    ffmpeg -i 2026-09-19_135052_cyber.wav -c:a libmp3lame -b:a 192k 2026-09-19_135052_cyber.mp3
